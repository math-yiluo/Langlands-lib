## The canonical Henselian projection

All adapted names below are relative to
`Langlands.NYLL.ValuationTheory.DiscreteValuationField.CompleteDVF`.
Throughout, `K : Type u` carries a supplied `[Field K]`, and
`F : CompleteDVF.{u, v} K` is any bundle of the published structure. The
universes `u` and `v` stay independent in every declaration; the field
`K` is implicit and `F` is explicit.

`toHenselianDVF F : HenselianDVF.{u, v} K` is the forgetful projection.
Its fields are exactly:

| Field of `HenselianDVF` | Value |
| --- | --- |
| `ValueGroup` | `F.ValueGroup`, the chosen value group in `Type v` |
| `instValueGroup` | `F.instValueGroup`, its stored `LinearOrderedCommGroupWithZero` structure |
| `valuation` | `F.valuation`, the chosen valuation, unchanged |
| `instRankOneDiscrete` | `F.instCompleteDiscrete.isRankOneDiscrete`, the stored rank-one discreteness |
| `instHenselian` | `IsAdicComplete.henselianRing F.valuation.valuationSubring (IsLocalRing.maximalIdeal F.valuation.valuationSubring)` |

So the underlying `DVF` has the same chosen value group, ordered-group
structure and valuation as `F`. The first four fields form the `DVF`
parent of the `HenselianDVF` structure.

The `instHenselian` field has type
`HenselianRing F.valuation.valuationSubring
(IsLocalRing.maximalIdeal F.valuation.valuationSubring)`, which is
definitionally the declared field type
`HenselianRing toDVF.valuationSubring toDVF.maximalIdeal`. The ring is the
actual Mathlib valuation subring of `F.valuation`, and the ideal is its
canonical local-ring maximal ideal. The value comes from the existing
Mathlib instance `IsAdicComplete.henselianRing (R : Type*) [CommRing R]
(I : Ideal R) [IsAdicComplete I R] : HenselianRing R I` in
`Mathlib.RingTheory.Henselian`. Its single class premise is supplied by a
`letI`. The local instance
`IsAdicComplete (IsLocalRing.maximalIdeal F.valuation.valuationSubring)
F.valuation.valuationSubring` is the proof
`F.instCompleteDiscrete.isAdicComplete` already stored in the bundle. No
completeness premise is added, and the local instance is not exported.
The Henselianity proof is thus assembled from published data and an
existing Mathlib result. The module states no new Henselianity theorem.

Lean auto-abstracts the proofs in this body into auxiliary constants
`toHenselianDVF._proof_1` to `_proof_4`. They are, in order: the stored
rank-one discreteness; the instance proofs
`SubsemiringClass (ValuationSubring K) K` and
`IsLocalRing F.valuation.valuationSubring`, which occur in the type of the
Henselian field; and the displayed `IsAdicComplete.henselianRing`
application. They are generated by the elaborator and are not separately
authored declarations.

## Canonical DVF path and residue data

In this table `F : CompleteDVF.{u, v} K`.

| Declaration | Type | Body |
| --- | --- | --- |
| `toDVF F` | `DVF.{u, v} K` | `F.toHenselianDVF.toDVF` |
| `valuationSubring F` | `Type u` | `F.toHenselianDVF.valuationSubring` |
| `maximalIdeal F` | `Ideal F.valuationSubring` | `F.toHenselianDVF.maximalIdeal` |
| `residueField F` | `Type u` | `F.toHenselianDVF.residueField` |
| `residueMap F` | `RingHom F.valuationSubring F.residueField` | `F.toHenselianDVF.residueMap` |

All six declarations, including `toHenselianDVF`, are reducible `abbrev`s.
`toDVF` is read along the single path
`CompleteDVF → HenselianDVF → DVF`; no second `DVF` is constructed.
Unfolding the published `HenselianDVF` and `DVF` abbreviations identifies
`valuationSubring F` with the type underlying
`F.valuation.valuationSubring`, whose elements are the `x : K` with
`F.valuation x ≤ 1`. The maximal ideal is
`IsLocalRing.maximalIdeal F.valuation.valuationSubring`, the residue field
is `IsLocalRing.ResidueField F.valuation.valuationSubring`, and the map is
`IsLocalRing.residue F.valuation.valuationSubring`. Thus the residue field
is the actual quotient by the maximal ideal, and the map is the canonical
quotient homomorphism. No alternative ideal, quotient or map is chosen.
Both the valuation ring and the residue field stay in the field universe
`u`. The ring, local-ring and residue-field structures are the canonical
Mathlib instances.

Defining these abbreviations adds no instance. In particular,
`inferInstance` does not find `HenselianRing F.valuationSubring
F.maximalIdeal` through these abbreviations. Such a proof is available
explicitly as `F.toHenselianDVF.instHenselian`. The source supplies its
corresponding Henselianity, adic-completeness and DVR results as the later
rows M107.013 onward, which are outside this module.

The source body of `toHenselianDVF` writes
`toDVF := { ValueGroup := F.ValueGroup, valuation := F.valuation }`.
There, instance search fills the ordered-group structure and rank-one
discreteness from `F`'s instance fields. The adaptation writes the four
parent fields directly, and it names the same stored instances
explicitly. This flattened form elaborates to the constructor application
`HenselianDVF.mk (DVF.mk F.ValueGroup F.instValueGroup F.valuation _) _`
with no intermediate `let`, so the same data are recorded more directly.

The source proves `instHenselian` by tactics. It first uses `change` to
restate the goal at `F.valuation.valuationSubring`, then applies
`Valuation.henselianRing F.valuation` (lines 76–80). That NYLL theorem
installs `Valuation.isAdicComplete F.valuation` as a local instance and
calls `infer_instance`, which finds Mathlib's `IsAdicComplete.henselianRing`.
The adaptation inlines exactly that route as a term. The `letI` binds
`F.instCompleteDiscrete.isAdicComplete`, the class field projection that
the source theorem `Valuation.isAdicComplete` (lines 39–41) merely
restates. Then `IsAdicComplete.henselianRing` is applied explicitly to
the actual valuation subring and maximal ideal. The elaborated term has
the displayed field type without a `change` step. Neither
`Valuation.henselianRing` nor `Valuation.isAdicComplete` is ported, and no
helper theorem or `Prop` is introduced. Since `HenselianRing` is a `Prop`,
this changes only the proof term, not the data.

The two imports are
`Langlands.NYLL.ValuedFieldTheory.Valuation.DiscreteValuationField.Complete.Definitions`
and
`Langlands.NYLL.ValuedFieldTheory.Valuation.DiscreteValuationField.Henselian.Definitions`.
The first supplies the published `CompleteDVF` and
`Valuation.IsCompleteDiscrete`. The second supplies `HenselianDVF` with
its residue-data abbreviations. It already imports the published `DVF`
module and `Mathlib.RingTheory.Henselian`, which contains
`IsAdicComplete.henselianRing`. These replace the source imports of
`DiscreteValuationField.Henselian`, `DiscreteValuationField.AdicPower` and
`DiscreteValuationField.ValuationTransport`. No external NYLL module
closure is imported.

Only M107.007–012 is extracted. The source rows M107.002–005 are outside
this module: the theorems `Valuation.isAdicComplete` and
`Valuation.henselianRing`, the instance
`Valuation.isCompleteDiscrete_comap_ringEquiv`, and the maximal-ideal-power
membership theorem. So are M107.013 onward: the DVR, adic-completeness
and Henselianity results for `CompleteDVF` (including the instance
`instIsAdicComplete`), and its membership, residue, uniformizer and
maximal-ideal-power results. Constructing a `CompleteDVF` from an ambient complete
field, the existence and uniqueness of chosen valuations on finite
extensions, integral-closure results and host comparisons are also not
part of this unit. It proves no completeness, topology or existence
statement.

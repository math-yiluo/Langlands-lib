# All of Mathlib except the three modules that clash with weil-conjectures

Module `Langlands.MathlibBase`. It imports every module that Mathlib's umbrella file `Mathlib.lean`
imports (`Std`, `Batteries` and 8,621 modules of Mathlib at commit `56a0058`), in the same order, except
three. It declares nothing.

## Why a module that declares nothing

The Library depends on weil-conjectures, a package it cannot change. Three modules of Mathlib each declare
a name that weil-conjectures also declares in its own sources:

| Mathlib module | Declarations also in weil-conjectures | Module of weil-conjectures |
|---|---|---|
| `Mathlib.CategoryTheory.GuitartExact.Prod` | `CategoryTheory.TwoSquare.GuitartExact.prod` | `WeilConjectures.FromJoel.CategoryTheory.GuitartExact.Basic` |
| `Mathlib.RingTheory.Depth.Basic` | `Ideal.depth`, `IsLocalRing.depth` | `WeilConjectures.RingTheory.Depth` |
| `Mathlib.RepresentationTheory.Stabilizer` | `Representation.stabilizer` | `WeilConjectures.RepresentationTheory.GeometricConstituents` |

A module that has one of these Mathlib modules and the corresponding module of weil-conjectures in its
import closure is rejected by Lean ("environment already contains …"). With `import Mathlib` every
Library file that imports all of Mathlib has the three in its closure, so no such file could ever be
loaded together with weil-conjectures, whatever the Library itself declares. No module of Mathlib imports
any of the three, and weil-conjectures imports none of them; so it is enough to leave them out of the
umbrella import. That is all this module does: the Library imports `Langlands.MathlibBase` wherever it
would import `Mathlib`, and a file that does so sees the same declarations as before, less those of the
three modules.

The file is generated by `notes/reuse/flt-names/make_mathlib_base.py` from `.lake/packages/mathlib/Mathlib.lean` and is
not edited by hand; run the script again when the Library's Mathlib moves. The script stops if one of the
three modules is no longer in `Mathlib.lean` and warns if some Mathlib module starts importing one of
them. `notes/reuse/flt-names/replace_mathlib_import.py` replaces `import Mathlib` by `import Langlands.MathlibBase` in a
tree.

## Rule

A Library file that needs a declaration of one of the three modules imports that module explicitly,
beside `Langlands.MathlibBase`. Such a file, and every module that imports it, cannot be loaded together
with the part of weil-conjectures that lies above the corresponding module of weil-conjectures in the
table. Nothing in the Library is renamed because of these three clashes: they are between Mathlib and
weil-conjectures.

## Checks

- With Lean 4.35.0, `import Langlands.MathlibBase` together with `import WeilConjectures` is accepted,
  whereas `import Mathlib` together with `import WeilConjectures` is rejected on
  `CategoryTheory.TwoSquare.GuitartExact.prod`.
- The modules loaded by `import Langlands.MathlibBase` are exactly those loaded by `import Mathlib`, less
  `Mathlib` itself and the three modules of the table.
